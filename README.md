# Furni

SaaS 3D-конфигурации и планирования мебели для мебельных магазинов.

- Полное ТЗ: `docs/SPEC.md`
- Правила разработки: `CLAUDE.md` (читаются Claude Code автоматически)
- Что делать дальше: `docs/BACKLOG.md`

## Запуск

```bash
pnpm install
cp .env.example .env
pnpm models:test    # демо-модели тенанта test, без них планировщик пуст
pnpm db:up          # postgres, redis, minio в docker
pnpm db:migrate     # миграции, роль приложения, RLS-политики
pnpm db:seed        # демо-тенант test: товары, материалы, опции, правила
pnpm dev
```

В БД две роли и два адреса подключения: `DATABASE_ADMIN_URL` — владелец схемы
для миграций, `DATABASE_URL` — роль приложения `furni_app`. Под суперпользователем
политики RLS не применяются, поэтому рантайм обязан ходить второй ролью.

Планировщик открывается на http://localhost:5173/planner?perf=1 — параметр
включает оверлей с fps и мост `window.__furni` для отладки.

Требуется Node 22+, pnpm 9+, Docker. Blender 4.x нужен только для обработки
моделей клиента: демо-каталог тенанта `test` генерируется без него.

## Демо-каталог

Моделей реального клиента пока нет, поэтому пайплайн и перф-гейт работают на
сгенерированном каталоге тенанта `test`: пять изделий с настоящей геометрией,
процедурными текстурами и тремя уровнями LOD. Источник — `tools/pipeline`,
результат — `apps/web/public/assets/test/` (в git не хранится, генерируется
командой выше).
